# Kiku 助手设计访谈

状态：创建流程及基准分支选择已实现、隔离集成测试通过；Herdr worktree 管理行为迁移已获实施授权，规范及任务图见 [worktree 管理规范](../.scratch/worktree-management/spec.md)。
日期：2026-10-20。

## 已确认的产品行为

1. 使用 Tern 原生选择框和输入框，对齐 lazygit 的工作树创建步骤。
2. 提供「新分支 + worktree」「已有分支 + worktree」「Detached worktree」三种方式，默认选中新分支方式。
3. 使用当前聚焦终端目录所属的 Git 工作树作为来源；新分支与游离工作树默认基于发起时的 HEAD，也可选择本地分支或已获取的远程跟踪分支作为基准。
4. 未提交修改保留在来源工作树，目标工作树从已提交内容开始。
5. 首版支持本机 Git 项目；远程会话暂不支持。
6. 创建成功后打开并聚焦新 Tern 标签页，终端进入目标工作树目录，分支模式使用分支名命名标签页。
7. 首版不自动复制 .env、不安装依赖、不执行项目初始化脚本。
8. 选择框支持键盘筛选、回车确认；Esc 取消当前创建流程。

用户在第一轮回答「全按推荐」。

## 第二轮已确认决定

1. 默认快捷键 Ctrl+B → Shift+G（`ctrl+b>shift+g`）；通过插件 config.json 的 keybinding 配置，也允许通过 Tern keybinds 覆盖，并提供命令面板入口。用户于 2026-10-20 将此前确认的快捷键调整为此序列。
2. 目录候选对齐 lazygit 0.65.1：已有 linked worktree 的父目录、插件配置的默认父目录，去重；无候选时使用主仓库上一级目录。每项显示完整目标路径，最后提供「其他目录」。分支名中的 / 保留为目录层级，ASCII 空格转为 -。
3. 已有分支支持本地分支及已获取的远程跟踪分支，不自动 fetch；已被工作树占用的分支不可再次检出。
4. 路径或分支冲突时保留输入并允许修改重试，不覆盖或强制删除。Git 创建成功但标签页打开失败时保留工作树并显示完整路径。

## 分支基准选择

用户于 2026-10-20 要求支持选择基于某个分支创建 worktree。实现沿用原生选择框：

- 新分支与 Detached 模式先选创建基准，再输入名称；第一项为发起操作时的当前 HEAD。
- 本地分支和已获取的远程跟踪分支按组列出，支持输入筛选；已被工作树占用的本地分支仍可作为起点。已有分支检出模式继续排除被占用分支。
- 使用完整 ref 解析所选分支，避免同名 tag 歧义；将解析出的 commit OID 固定为创建基点，路径或名称重试仍使用此 OID。
- 目录选择框显示基准名称和提交短哈希；重新选择创建方式时清除旧基准信息。
- 不 fetch、不切换来源分支，也不因选择远程基准建立 upstream；需要本地跟踪分支仍使用“已有分支 + worktree”。
- 在基准选择框按 Esc 取消，不创建分支或工作树。

## Herdr worktree 管理行为迁移（设计已确认）

用户要求根据现有 Tern SDK 评估迁移 Herdr 的 worktree 管理功能。

- 已确认：以创建、列出、打开／切换、安全移除的管理行为对齐为目标，界面和工作区组织使用 Tern 原生能力，不要求一比一复制 Herdr workspace 界面。
- 已确认：管理当前仓库的全部 worktree，包括 Git、lazygit、Herdr 等外部工具创建的；以 Git 实际状态为准。主工作树可打开，但不能从插件移除。
- 已确认：沿用一棵 worktree 对应一个命名标签页，标签页内可拆分 pane，不改为每棵 worktree 一个独立 session。
- 已确认：本轮仅覆盖本机 macOS/Linux，继续拒绝远程会话操作。
- 已确认：保留当前 lazygit 对齐目录策略、`defaultPath` 和自定义路径，不采用 Herdr 集中目录规则，不搬迁已有工作树。
- 已确认：打开时优先复用当前窗口可见会话中的有效绑定标签页；有多个候选时让用户选择，没有候选才新建，不自动合并或关闭。
- 已确认：关闭只针对选定的绑定标签页；检测到运行中命令、未保存内容或安全状态无法判断时拒绝自动关闭，通过检查后仍需确认。不提供插件内强制关闭。
- 已确认：移除前先关闭当前窗口可见会话中仍在使用该工作树的环境；关闭与移除分为两步。外部终端和其他工具的使用情况仍由用户确认。
- 已确认：提供独立的危险移除入口，展示将丢弃的内容并要求再次输入目标路径。正常移除保持保守，不删除分支，也不自动 merge 或 push。
- 已确认：危险入口可舍弃本地已修改、未跟踪和忽略文件，但不能移除主工作树、锁定工作树、仍被可见环境使用的工作树或身份／状态未知的路径；不自动 unlock，不使用双重 `--force`。
- 已确认：没有分支或标签保护的 Detached 提交属于危险移除情形；正常移除停止并提示先保留提交，危险入口可在展示提交风险和再次确认后允许放弃，不自动创建或删除分支。
- 已确认：保留 `Ctrl+B → Shift+G` 的新建行为，另加「Kiku: 管理 Git worktree」命令，允许单独配置管理快捷键，默认不新增绑定。
- 用户在设计访谈时确认先记录、暂不实施；随后调用 `implement-spec` 授权按已确认设计实施。后续范围、验收和进度以关联规范及 tickets 为准。

### SDK 可行性核验

本机实际版本：Herdr 0.9.5；Tern 0.9.5（2863c37）。已运行 Herdr 只读 CLI 帮助，并通过 `tern plugin types <临时目录>` 导出本机 SDK 声明，未修改日常配置。

- Herdr 的 `worktree create/list/open/remove` 对应创建、发现、打开和移除；`workspace close` 只关闭界面状态，`worktree remove` 使用 Git 移除 checkout 且不删除分支。创建的 worktree workspace 与父仓库 workspace 分组。来源：[Herdr v0.9.5 CLI reference / Worktrees](https://raw.githubusercontent.com/herdrdev/herdr/v0.9.5/docs/next/website/src/content/docs/cli-reference.mdx)。
- Tern 提供 `cx.session:tabs/panes`、`cx.sessions:list/create/switch/close`、`cx.layout:tab/focus/close`，可组合实现工作树发现、打开复用及环境关闭。worktree 的 Git 操作仍由插件通过 `tern.process.run` 执行；SDK 没有专用 worktree 管理接口。来源：本机 `tern.d.luau` 的 `SessionCx`、`SessionsCx`、`LayoutCx`、`GitCx` 声明及 [Window API](https://docs.stencil.so/tern/reference/api-window.html)。
- `cx.layout:close` 和 `cx.sessions:close` 不带交互确认或锁保护；不能将“Git 工作区干净”等同于“可安全结束程序”。安全确认、操作范围以及 Git 失败时的处理必须由插件实现。来源：本机类型声明及 [Sessions and hosts cx](https://docs.stencil.so/tern/reference/api-window.html#sessions-and-hosts-cx)。
- `snapshot/restore` 保存现存布局而非程序；pane 已增删或 session 消失后可能拒绝恢复。不可用它承诺重启后恢复任意运行中的命令。来源：[Layout cx](https://docs.stencil.so/tern/reference/api-window.html#layout-cx)。
- 进程和文件操作在对应 VM 所在机器执行，窗口插件的 `tern.process.run` 不因当前焦点在远程会话就自动成为远程执行；远程 worktree 管理需要单独设计执行通路。来源：[Shared API](https://docs.stencil.so/tern/reference/api-shared.html)。
- 多窗口共用 `tern.kv`，但并发写入为最后一次重命名获胜，不能用它代替跨窗口互斥锁；SDK 未提供原子的“查找或创建工作树环境”操作。来源：[Storage](https://docs.stencil.so/tern/reference/api-shared.html#storage)。

隔离 Tern 实例实际通过五项探针：跨会话枚举 tab/pane/cwd 与关联 ID、切换并聚焦已有 tab、恢复现存 tab 布局元数据、关闭指定 tab 的最后一个 pane、关闭指定 session 且保留另一个 session。探针仅操作临时实例中的自建环境，没有操作用户会话或真实工作树。

报告：`/private/tmp/tks-l5staddh/report.json`。探针准备期间修正了控制命令的 Lua 字符串传参、macOS Unix socket 路径长度和 `PaneInfo.pane` 字段使用；最终五项全部通过。尚未验证远程执行、多窗口并发及完整 worktree 移除流程。

### 已确认的边界

- 仅迁移 `Ctrl+B → Option+G` 打开 lazygit、`Ctrl+B → t` 打开临时终端，优先保留原使用习惯，不调整已有 worktree 流程或其他快捷键。
- 接受 Tern 原生浮窗，不改用临时标签页；接受默认小尺寸与四角定位，不要求复制 Herdr 的居中、百分比尺寸。
- 本轮所有功能仅支持本机 macOS/Linux；远程能力由用户明确延后到后续统一实现。新工具必须确认来源属于本机，远程或主机身份不明时明确拒绝，不在本机执行远程路径，不识别本地 shell 内手动建立的 SSH 子会话，不预建半成品远程通路。
- 两项工具均从触发时来源窗格的当前目录启动，不强制切到 Git 工作树根目录；lazygit 自行识别仓库。无法可靠取得目录时提示错误，不猜路径。
- 每个来源窗格最多各有一个 lazygit 和一个临时终端；重复触发聚焦已有实例，不重复创建或结束程序。不同来源窗格不串用；实例存活时保留其自身目录，退出后重建才读取来源的新目录。
- 第三方程序优先使用本机手动路径，未配置或显式路径无效时允许回退本机 `PATH`；均不可用时不启用对应启动功能，具体规则见下文“命名与第三方程序依赖”。临时终端使用 Tern 默认 shell，不自动安装程序。
- 采用“收起保活 + 显式结束”，不照搬 Herdr 必须退出程序才能返回的体验：`Ctrl+B → q` 收起当前插件工具并返回来源窗格，原打开快捷键恢复／聚焦；`Ctrl+B → Shift+Q` 明确结束当前插件工具。结束运行中或状态不明的工具前确认，不全局抢占裸 `Esc`、`Ctrl+C`，不删除工具中创建的文件。
- 工具正常退出后关闭浮窗；失败需保留可查看的错误，不一闪而过。无法确认进程代次的失败卡片交由 Tern 原生查看／关闭，插件不凭历史标记继续管理。
- 同一来源一次只显示一个工具浮窗，默认右下角；打开另一工具时收起前者但保留程序。浮窗内触发另一工具仍使用原来源，不形成嵌套工具归属。
- 来源窗格单独关闭后不自动杀掉仍存活的工具，也不把它绑定到其他来源；本次插件运行期内，身份已确认的工具可通过“恢复收起的工具”命令找回，列表显示主机与目录，选中后恢复成独立终端标签页，不突然自动跳出新标签页。
- 原生回归与 SDK 身份能力审查后，用户明确选择安全模式：本轮取消跨插件重载自动接管。重载后旧终端与任务保持原状，不自动收起、移动、结束或重跑，改由 Tern 原生管理。历史标记、旧 pane ID 和一个仍存活的 PID 不构成候选窗格的归属证明；Restart 或进程代次无法确认时停止插件管理。远程断线与重连留待未来统一支持远程时实现。
- 保活不是阻止用户结束进程：不替代 Tern 对整个标签页、会话或宿主的原生关闭规则，不承诺在这些操作终止程序后复活任务。
- 沿用现有快捷键配置与命令面板入口惯例，尊重用户 Tern keybinds 覆盖，不修改已有 worktree 创建／管理绑定。收起和结束仅作用于插件工具，不把普通窗格当作工具关闭。

### 已核实的来源与平台差异

- 用户 Herdr 配置中，`prefix+alt+g` 执行 `/opt/homebrew/bin/lazygit`，popup 尺寸为 `90% × 90%`；`prefix+t` 执行 `exec "${SHELL:-sh}"`，popup 尺寸为 `80% × 80%`；前缀为 `ctrl+b`。

- 隔离 Tern 实例已实际验证终端创建、转为浮窗、停放、恢复为浮窗和关闭；截图显示原生四角小浮窗。此核验不代表两个新操作、快捷键或远程执行已经实现或通过验收。
- 本轮核验文件位于 `/tmp/tkp-Nq5MZO/`，截图为 `shots/serve/floating-terminal.png`；隔离实例及自建窗格已关闭。
- [Tern Layout／Launch 契约](https://docs.stencil.so/tern/reference/api-window.html#layout-cx) 明确 `split` 在目标 pane 所属主机创建终端，`Launch.command` 由该 pane 的 login shell 执行；普通插件的 launch 不能据此推断继承本地 shell 内手动建立的 SSH 会话。远程实机执行尚未验证。
- 补充隔离探针确认：收起的终端在来源窗格关闭后仍存在，可通过 `move_to_new_tab` 恢复为独立终端；可见浮窗在其唯一 tiled 来源关闭后仍存活，但被 Tern 转为普通 pane，插件仍需按已确认策略处理归属。

- 补充原生证据：`tern-kiku-test-z6g4pw39` 中，普通窗格仅展示旧工具 prefix 文本，恢复扫描便错误认领该窗格。Tern 0.9.5 的 `PaneInfo` 不提供 shell PID／进程代次，进程列表也不提供 pane 绑定；因此不能把旧进程仍存活当作当前候选窗格的身份。用户据此批准上述安全模式，而非降低身份检查以保留启发式恢复。

### 实施验收契约

以下为本轮实现遵循的验收要求；macOS 实际结果与验证限制见 [验证记录](verification.md)，不代表 Linux 已实测：

1. 两个打开快捷键在来源目录、来源主机上创建正确工具，且不改变既有 worktree 操作。
2. 同源重复打开复用同一实例；从工具内切换不形成嵌套，另一工具自动收起；不同来源不串用。
3. 收起前后的程序身份、当前目录与运行任务保持，恢复不重新执行启动命令；裸 Esc、Ctrl+C 仍交给程序。
4. 显式结束身份已确认的工具时，空闲 shell 可直接关闭；存在运行中程序或安全状态无法确认时必须确认，取消不改变工具状态。正常退出关闭视图，失败原因可查看；身份代次未知时即使确认也不得由插件关闭。
5. （lazygit 部分已由文末调整取代）非 Git 目录可打开临时终端；lazygit 的仓库交互交给程序，插件不自动初始化仓库。目录未知、程序缺失、启动或浮动失败时明确显示主机、目录和原因，不误报成功，不自动杀掉已经启动的任务。
6. 来源单独关闭后，本次运行期内身份已确认的存活工具可从恢复入口找回；重载后旧实例保持原样，不重新接管、重复启动或串到另一来源，普通窗格展示旧工具文本也不获得工具归属。
7. 本机执行、cwd、shell、收起与恢复使用真实 Tern 验证；远程上下文必须安全拒绝。远程实机验收不属于本轮范围，后续统一实现远程时再验收。

### 单实例管理方案

- **范围与索引**：注册表在当前窗口插件 VM 内；将创建 tab ID、启动目录和工具类型分别做长度前缀编码，不让含分隔符的路径造成键碰撞，不按标题、工具当前 cwd 或进程名扫描认领普通终端。主机与会话信息用于操作前验证。
- **单一注册表**：`plugin/lib/tools.luau` 的 `tools` 按固定归属键映射实例，`byPane` 提供反向索引，`pending` 按完整归属键管理进行中的操作。旧的“host + session + source pane”复用与同源互斥浮窗规则已移除，不维护第二套来源归属。
- **先占位，再异步创建**：捕获触发时的 tab／聚焦窗格／继承目录，在依赖检查、身份准备和创建之前占住归属键。连续触发同键不会重复创建；占位覆盖启动或复用布局恢复的整个异步过程。完成回调核对仍是同一操作代次，不能释放后来操作的占位。
- **已有实例路径**：登记存在且 pane／主机／会话／进程身份仍可确认时，恢复已决定的默认布局并聚焦，不重新执行启动命令，不重置工具内部 cwd。工具被移到别的 tab 或被 `park` 不释放归属键。
- **关闭与不确定状态**：正常返回 `nil` 且无新增候选时释放创建占位；异常且有候选时等待候选确认关闭；异常无候选时也保留不确定占位，提示用户原生检查后重载，不把一次枚举无新增视为回滚保证，也不安排无目标轮询。Restart、失败卡片或进程身份不明时不移动、结束或重跑。
- **异步上下文**：执行布局操作前再次核对触发 tab、目录、聚焦上下文及目标记录；变化时不把迟到的结果移动到用户后来切换的工作区。已经创建的程序不因焦点变化被自动杀掉。
- **联合授权**：单实例先核对父进程，再以子进程启动代次作为最后一次异步核验；从受管工具复用另一工具时，来源与目标及其父进程须同时存在于一份完整的新采样中，截断、缺失或未知则拒绝。从工具新建另一工具时，token／依赖／Git bridge 准备完成后再次核验来源。SDK 仍是采样而非 OS 原子身份操作，不据此承诺绝对消除宿主时序竞争。
- **不是全局锁**：每个 Tern 窗口有独立 VM，pane/tab ID 也不能跨窗口直接比较。本方案保证当前窗口本次运行期的受管实例去重，不承诺多个窗口同时显示同一会话并并发打开时全局唯一；普通 `tern.kv` 持久化不提供原子互斥，不能充当跨窗口锁。用户已确认此范围。来源：[窗口与布局](https://docs.stencil.so/tern/guides/layout.html)、[架构](https://docs.stencil.so/tern/concepts/architecture.html)。

### 静默启动与身份交接（2026-10-22）

用户截图确认旧实现会把 `KIKU_TOOL_V1` 握手命令及输出留在新终端里；窗口 API 的 `cx:run` 就是“像键入一样”写入 PTY，没有静默选项。因此身份采集改到进程启动阶段，且不改变工具 pane 的原生终端类型。

- **私有启动目录**：每次创建先申请 `<plugin data>/tool-start/<随机32位标记>/`，写入 `request.json`（版本、标记、真实启动目录），再以该私有目录作为 `layout:split` 的 `cwd`。它同时是本次启动的许可与归属关联，普通 pane 不会进入该根目录。
- **宿主 spawn 钩子**：`plugin/host.luau` 在 daemon 侧注册 `tern.on("spawn", identity.spawn)`。只有 `spec.cwd` 精确等于上述根下合法标记目录、且 request 校验通过时才改写；其他 pane 原样返回。插件块不会触发该钩子，钩子内不做异步等待。
- **保真 shell**：`Launch.command` 非空会让 pane 变成 agent 类型并改变程序／标题，因此不用它传递命令。钩子保留已解析的 `program` 与 `env`，把 `args` 换成一次性初始 shell（zsh `-f -c`、fish `--no-config -c`、bash/sh/dash/ksh `-c`）：在 exec 原 `program` 与原 `args` 前用 `noclobber` 静默写入 shell 的 `$$`，随后 `exec`，所以记录的 PID 就是最终交互 shell。默认 shell、登录参数和 Tern 的 shell integration 环境仍由宿主在钩子之后提供。此前用 `cx.run` 注入的 `printf` 全部移除，不做清屏或 ANSI 擦除。
- **首代次语义**：`pid` 文件只允许创建一次；原生 Restart 会重新执行同一启动目录，但不会覆盖首代次 PID。窗口侧仍以进程采样核对 PID、父进程与启动代次，因此新 shell 一律判为身份不明，不接管、不结束、不重跑。
- **失败与不支持**：request 缺失或校验失败时钩子不改写，终端按默认 shell 启动但没有身份记录，窗口超时后保留 pane 并提示不重复启动。默认 shell 不受支持时钩子写入 `error` 并让 pane 以 125 退出，窗口显示具体原因；不静默降级为无身份工具，也不删除用户文件。
- **清理**：插件正常结束或观察到 pane 消失时删除该标记的记录与私有目录，只触碰自己的启动根；不删除 `request.cwd`。原生 Restart 失败卡片、重载后的旧实例仍按安全模式交回 Tern。
- **边界**：宿主半部是本机制的前提；关闭它会导致工具身份无法确认（安全拒绝，不是无身份启动）。窗口 VM 的 `tools/` 记录仍跨窗口共享，私有启动目录按标记隔离，不用共享 KV 充当锁。

### 外部程序解析回退（2026-10-22）

- 用户报告打开 lazygit 提示“executables.lazygit 与本机 PATH 均不可用”，但本机 `/opt/homebrew/bin/lazygit` 存在。原因是依赖探测读宿主进程 `PATH`；Finder／daemon 启动的 Tern 不继承 shell 配置里的 Homebrew 目录，而 `git` 因 `/usr/bin/git` 存在所以未暴露问题。
- 解析顺序保持：显式 `executables.<name>`（绝对路径或插件目录相对路径）→ 探测失败回退进程 `PATH`；若仍未命中，再用本机登录 shell 读取一次用户 `PATH`（`$SHELL -l -c`，缺失时按平台取 `/bin/zsh`／`/bin/sh`），只重试缺失项并按 VM 缓存。
- 成功回退后，工具启动环境使用“登录 PATH + 进程 PATH”，登录目录在前；不覆盖显式配置，不修改 shell 配置，不自动安装程序。登录 shell 不可用或输出异常时保持原有的缺失提示，依赖仍按功能独立门控。

### PiP glance 与 leader 目标（2026-10-22）

- 用户报告：打开的临时终端浮层停留一段时间后，`Ctrl+B → q` 与 `Ctrl+B → Shift+Q` 报“工具身份未确认／未识别当前窗格”。原生隔离复现显示 pane 仍存活、身份记录仍在，变的是焦点。
- 原因：Tern 在窗口失焦或点击底层 pane 后，把该 PiP 从 `mode=focus` 降为 `mode=glance`（缩小、倾斜）并把聚焦交回 owner pane。旧实现只按 `byPane[cx.session:focused()]` 取目标，因此 glance 状态必然查不到工具。观察器、进程代次校验和 `park` 判定都没有问题。
- 修复：`plugin/lib/tools.luau` 的 `leaderTool` 先按聚焦 pane 命中；未命中且当前标签页存在本插件登记、`floating`、未 `parked`、未 `exited` 的临时终端时，唯一候选即作为 leader 目标。多个候选不猜测，提示先点击目标浮层；零候选保留原提示。
- 边界不变：候选只在当前 host／session／标签页内，其他标签页的浮层不受影响；`q` 仍是 `park` 保活，`Shift+Q` 仍先弹确认；进程身份校验、异步上下文核对和“不接管未知实例”的规则全部沿用。

### 已确认的补充边界

- 唯一性按创建时的归属 tab 约束插件新建，而非扫描屏幕强制去重：把 T1 的实例移到 T2，不会改变其 T1 归属；T2 可以有自己的同目录实例，不自动关闭任意一个。
- 来源窗格不再是生命周期归属：单独关闭来源不主动停放或结束工具，由 Tern 处理其布局。原生关闭整个 tab／session／宿主可能结束工具，插件不拦截或复活。仍存活的停放临时终端保留专用恢复入口；原归属 tab 已不存在时，由用户显式选择恢复到当前 tab，并重新建立归属，遇到已有同键实例时先选择，不静默替换或杀进程。lazygit 不增加专用孤儿恢复流程。
- `q` 停放后优先返回最近一次唤出该终端的窗格；该窗格已不存在时沿用 Tern 的焦点结果，不重新创建来源。重复打开已聚焦的目标时不得把目标当作自己的分屏／浮动承载者，也不得重复创建；恢复形态所需承载窗格已消失且无可靠替代时保持现状并提示。
- 目录键采用 Tern 原生继承到的绝对路径，不按仓库根合并子目录，也不额外合并符号链接等路径别名；继承目录或主机身份未知时提示，不猜测。工具进程身份不明时不移动／结束／重跑。
- lazygit 的程序退出呈现交给 Tern 原生行为；临时终端正常退出、错误保留及身份不明时交回原生的规则沿用现有契约。仍仅支持本机 macOS/Linux，远程、依赖解析、已有 worktree 流程和用户快捷键覆盖规则不变。
- 已授权实施，不提交或推送，不覆盖用户配置。本轮更新运行代码、使用说明与相关测试；新增验证仅包括静态检查和获准的隔离 SDK 边界逻辑测试。2026-10-22 用户另行批准一次最小隔离原生验证：使用私有配置、daemon、控制 socket 与临时目录，不连接或重载用户日常 Tern；其余原生套件仍未运行，不改写历史实机验收结论。

### 实施验收要求

- 同 tab 同启动目录由不同来源打开时复用；不同工具类型、不同归属 tab 和不同启动目录互不混用；并发／连续触发不产生同键重复实例。
- 工具内 `cd` 不改变固定归属，但新操作的目录继承仍取当前聚焦窗格；非 Git 目录可打开临时终端（lazygit 现会在启动前拒绝非仓库，见文末），lazygit 不被强制切到根目录。
- （已由文末调整取代）lazygit 始终按默认右侧 block 呈现，临时终端按右下角 PiP 呈现；复用、手动停靠后重开、跨 tab 移动后找回均不重启程序，不改变任务状态，不关闭无关 pane。
- 临时终端原生 PiP 交互、`q` 停放／恢复和 `Shift+Q` 安全结束分别验证；原生贴边隐藏与插件停放不能互相误判，不能连带隐藏其他 PiP。
- 来源关闭、原归属 tab 消失、正常退出／失败／Restart、重载后旧实例，以及与 worktree 使用中保护的交互均需回归；不将本轮官方 PiP 调查代替新实现验收。
- 用户已确认代码测试 seam：执行生产注册命令／事件入口，以隔离替身提供 Tern SDK 的布局、事件和进程采样，验证去重与安全状态转换；不测试私有函数、源码文本或 mock 转发回声，不以恒真替身跳过身份检查。原生回归脚本只更新契约并做语法检查，不执行。
- 最终交付明确保留真实 SDK 布局／焦点、shell 身份握手与原生生命周期时序未经新代码实机验证的风险；不把逻辑替身验证等同原生验收。

### 官方 PiP 交互核验（2026-10-21）

- 用户指定官方文档入口为 <https://docs.stencil.so/tern/>。本机实际版本为 `tern 0.9.5 (2863c37)`，本轮执行 `tern plugin types` 导出并核对 SDK。官方 [Built-in Actions](https://docs.stencil.so/tern/reference/actions.html#picture-in-picture) 列出 `new_browser_pip`、`pip`、`pip_dock:*`、`pip_corner:*` 与 `pip_stash_all`；[Pictures in Picture](https://docs.stencil.so/tern/scripts/pip.html) 给出聚焦、展开、缩放、拖动、贴边隐藏及停靠语义。
- 原生 GUI 隔离观察使用私有配置、daemon、控制 socket 和临时目录；执行真实 `new_browser_pip`，并打开当前插件的临时终端进行对照，没有浏览网页或操作用户日常会话。二者均显示原生 PiP 的返回分屏、展开及关闭控件；临时终端无需重做浮窗外壳即可使用这些交互。
- 临时终端实际通过 `pip resize` 调整尺寸、`pip expand` 展开／还原、`pip corner` 切换角落、`pip stash`／`unstash` 贴边隐藏／恢复、`pip dock` 返回分屏。点击底层窗格后，同一工具从 `focus` 变为 `glance`，仍然存在；恢复、停靠后仍为同一 pane，并可执行 shell 命令。最终通过原生关闭操作关闭该工具。
- 原生展开受所属 frame 限制：分屏后的终端浮窗展开填满来源窗格区域，而不是承诺填满整个 tab。官方文档同样说明显示尺寸受 frame 约束。
- 原生 `stash` 保留 PiP 与边缘标签，不加入会话 `park` 牌堆；实测 `pips[].mode = hidden`、`stashed = right` 且 `park.cards` 为空。现有插件 `q` 调用的是 SDK `layout:park`，会让 pane 脱离 tab，两者不是同一套恢复路径。
- 本机 SDK 提供 `float/dock/park/unpark`，未提供单个 PiP 的 `stash/unstash` 方法；已核对的内置动作仅提供全 tab 的 `pip_stash_all`，不能为了模拟单个终端收起而隐藏用户的其他 PiP。脚本 `pip stash` 的存在不等于窗口插件有同名 API。
- 对浏览器展开状态按 `Escape` 未退出展开；不能把裸 `Escape` 承诺成所有 PiP 的统一返回键，也不应据此抢占终端程序输入。拖动手势和浏览器失焦路径本轮未实际验证，只保留官方文档证据。
- SDK `split` 无比例参数，`TabSpec.ratio` 的默认一半只属于 workspace 建树。本轮决定采用原生尺寸，不据此承诺精确等分。
- 证据位于 `/private/tmp/kiku-pip-x3alk_pa/observations.json` 与同目录 `target/shots/tern/live/` 的截图；原生 GUI、私有 daemon 及控制 socket 已清理。没有修改实现、执行既有回归套件或把本轮观察表述为新方案验收。

## 工具统一浮动与激活描边（2026-10-22）

用户要求 lazygit 与临时终端使用同一种交互，并美化激活 block。本次决定：

- lazygit 不再以右侧 tiled block 打开，而是和临时终端一样在当前标签页的右下角创建原生 PiP；创建、复用、收起、结束和恢复共用 `plugin/lib/tools.luau` 的同一套路径。复用或再次打开时，被用户拖动、缩放或停靠过的工具都会恢复为右下角 PiP 并聚焦，不重启程序。
- `Ctrl+B → q`、`Ctrl+B → Shift+Q` 与“Kiku：恢复收起的工具”现在同时管理 lazygit 和临时终端；普通 pane 仍不会被这些动作关闭。结束确认文案会区分“结束此 lazygit”和“结束此临时终端”。
- lazygit 在创建 pane 前先用已解析的 Git 执行 `-C <启动目录> rev-parse --is-inside-work-tree`；不是 Git 仓库、检查超时或来源在检查期间变化时直接提示并停止，不创建 pane、不启动 lazygit。临时终端不受此限制。
- 同一固定归属（创建时 tab + 启动目录 + 工具类型）仍各保留一个实例；两类工具可以在同一标签页共存，`q` 在存在多个可见浮层且无法从焦点确定目标时仍拒绝猜测。
- 激活 block 由 `plugin/lib/style.luau` 通过 `tern.css("active-block", …)` 安装全局样式：使用主题 `--accent` 色的 2px 圆角描边，并移除 Tern 原先在激活 block 顶部绘制的 1px 渐变线。tiled 与 PiP 聚焦时也显示描边；float／studio 布局按 4px 内边距对齐卡片。
- Tern 0.9.5 的窗口插件 API 不暴露 PiP 的 `expand`／`resize`，场景脚本里的 `pip expand` 也不能通过 `cx:action` 或 `cx.actions:run` 调用。因此插件只能以 `focus` 模式打开（原生最大标准尺寸），自动展开到整块仍需要用户双击或使用原生交互；本轮不采用固定视口尺寸的 CSS 覆盖来伪造“最大化”，避免遮挡其他 pane 和破坏 PiP 拖动／停靠。
- 仍仅支持本机 macOS/Linux，依赖解析、身份校验、安全模式、worktree 流程和用户快捷键覆盖规则不变。

## 源码热加载与 Git 目录边界（2026-10-22）

- 用户要求保留源码热加载和当前旧 lazygit 进程。运行包整体位于仓库的 `plugin/` 子目录；Tern 直接链接该目录，不复制固定文件清单，不在仓库根保留第二份运行入口或配置。
- 隔离原生复现显示，Tern 0.9.5 会因已链接包目录内的 `.git` 元数据变化重载插件；当包根等于源码仓库根时，打开 lazygit 即可能中断创建后聚焦，并清空运行期工具登记。该问题不通过放宽身份校验或重新认领历史实例修复。
- `plugin/` 包含清单、窗口／宿主入口、`lib/` 与 `config.json`。新增运行文件放在该目录内，仍由 Tern 热加载；仓库根的 `.git`、测试和文档位于包外，不触发运行包重载。相对可执行文件路径仍按插件包目录解析。
- 真正修改插件源码仍会重载，因此旧工具继续遵循安全模式，由 Tern 原生管理；不自动关闭、迁移或重新认领。关闭并重新打开客户端也不授予旧工具管理权。
