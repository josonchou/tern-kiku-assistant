# 04 危险移除与完整管理验收

Status: resolved
Type: task
Blocked by: 02, 03

## 目标

提供独立、明确且不可越过硬保护的危险移除入口，完成管理工作流的原生交互和文档验收。

## 修改范围

03 的风险审查与管理交互、真实集成场景、`README.md` 和 `docs/verification.md`。复用已实现机制，不建立第二套危险状态判定。

## 交付契约

- 危险入口与正常移除明确区分，展示已修改、未跟踪、忽略文件以及未受保护 Detached 提交的风险；列表有长度限制时明确说明，不能把截断当作完整清单或安全结果。
- 需主动输入完整目标路径，不预填作为确认；明确确认无外部环境使用。错路径允许改正或取消，不产生删除。
- 最终操作前重新审查；身份、HEAD/分支、风险列表、锁定或使用者发生变化时停止并要求重新审阅。
- 允许丢弃被明确授权的本地内容或无保护 Detached 提交，但 main/bare/locked/prunable/使用中/身份或状态未知，以及未完成Git操作仍不可操作；不 unlock、不双重 --force、不强制关闭。
- 仅在安全审查与确认一致时执行单一 `git worktree remove --force -- <path>`。保持分支，不自动 merge/push/fetch；失败可能已部分移除目录或登记，只保留剩余现场，不自动补救或声称事务回滚。
- README 覆盖管理入口、配置、关闭/移除区分、风险及跨窗口/外部使用限制；最终实际验证记录由主线程补入。

## 验收

1. 危险内容在正常入口被拒绝；通过独立危险入口和正确完整路径后才删除目标，保留分支与其他文件。
2. 错误路径、取消、风险预览后新增内容或新使用者均不删除；可重新发起而不遗留流程锁。
3. 危险入口不能覆盖锁定、主工作树、使用中、路径身份不符、未完成Git操作等硬保护；文件状态干净时也要保留进行中操作的恢复信息。
4. 未受保护 Detached 提交可明确放弃，不自动建/删分支；已受保护 Detached 的正常路径保持有效。
5. 创建、发现、复用打开、安全关闭、正常移除和危险移除的完整真实回归通过，检查管理与确认界面截图。

## 测试与实施
